AI at work: six experiments
in systems engineering
Hands-on exploration of Claude across productivity, automation, and application building — from first conversation to deployed product.

Companion document. This report is the experimental record for the AI System Design playbook. That document establishes the theoretical framework — two tracks, six research domains, four competence pillars, a five-phase development cycle. This document records what was actually built and what each use case looks like in practice. The two are designed to be read together.

Three entry points — Chat, Cowork, Code
01
Claude Chat — claude.ai
Conversational interface in any browser. Output only — text you review and use manually. Files can be attached for analysis. No direct connection to your systems or applications. Best for: one-off tasks, drafting documents, explanation, brainstorming.
02
Claude Cowork — Projects
Chat with persistent memory. Skills, standards, and templates defined once, applied across every session automatically. The AI behaves like a trained team member from the first message. Best for: recurring team workflows, standards enforcement, shared institutional knowledge.
03
Claude Code — Terminal / Desktop App
Claude connected directly to your files, applications, and systems. Reads and writes files, builds and deploys software, controls desktop applications — without copy-paste. Also available as a native Mac/Windows desktop app integrated with Excel and PowerPoint. Best for: automation, live document manipulation, application building.

Track 1 · Augment · Experiment 01
Claude in Excel
Intelligent data work — from standardised model generation to live quality assurance inside your spreadsheets. The Claude desktop app integrates directly with Excel on Mac and Windows; Claude Code provides the same capability from the terminal.

The value is not speed — it is judgment. Claude's primary contribution to Excel work is applying engineering logic to data that already exists: catching inconsistencies, flagging impossible values, checking cross-sheet integrity, and verifying that data conforms to standards before a document reaches formal review. This catches the kind of errors that are embarrassing to have flagged by a customer.

Standardised engineering models supported
Requirements
Traceability Matrix · Verification matrix · Compliance tracker
Risk & Quality
Risk register · Anomaly log · Non-conformance tracker · Defect log
Programme
WBS · Schedule tracker · ICD log · Configuration register
Finance
Budget tracker · Cost-to-complete forecast · Earned value model
Step-by-step guide
01
Setup · Choose your entry point
Desktop App or Claude Code — both live, no copy-paste
Claude Desktop App (claude.ai/download): install once on Mac or Windows; Claude integrates with your open Excel file directly. Claude Code (claude.ai/code or terminal): point it at any .xlsx file; it reads the structure and makes changes programmatically. Both provide a live, direct connection to your spreadsheet — no switching windows, no copying output.
02
Generate · Create a standardised model from scratch
Describe the model — Claude builds it
Plain English is sufficient: "Create a Requirements Traceability Matrix for a power subsystem. Columns: Requirement ID, Description, Source, Verification Method, Responsible Engineer, Status. Apply colour coding: green = verified, amber = in progress, red = not started." Claude generates the structure, applies the formatting, and pre-fills example rows. A task that previously took half a day takes five minutes.
03
Validate · Logical consistency check on existing data
Ask Claude to check the logic of a completed spreadsheet
Point Claude at an existing file and ask: "Check this risk register for logical errors. Flag any row where the risk score doesn't equal Likelihood × Impact. Also flag any mitigation marked 'complete' where residual risk is still rated High." Claude reads every row, applies the logic, and returns a list of inconsistencies with exact row references. This replaces two hours of manual cross-referencing before a formal review.
04
Quality · Data quality assessment across the workbook
Structured quality report — issue, location, suggested fix
Ask: "Assess the quality of this budget tracker. Flag: missing values, duplicate cost IDs, any line item where sub-item totals don't match the parent, and any forecast dates that have already passed." Claude produces a structured report. You review and accept the fixes. The same logic applies to any engineering spreadsheet — the prompts are the quality criteria, not hard-coded rules.
05
Revise · Reformat to a new standard
Apply a new template or standard to existing data without data loss
When a standard changes or a customer requires a different format: "Reformat this requirements matrix to the AS9100 template. Add the missing columns, rename the existing ones, and preserve all existing data. Create a backup tab with the original before making changes." Claude restructures the entire workbook. No manual reformatting, no risk of data loss through cut-and-paste operations between files.

The logical-check use case is underutilised. Most engineers use AI to create documents faster. The higher-value use is verifying documents that already exist — particularly before a formal review. Claude catches what a tired engineer misses on a 200-row register at 5pm the day before a CDR.

Track 1 · Augment · Experiment 02
Claude in PowerPoint
From raw engineering notes to polished, audience-calibrated presentations — with no copy-paste. The Claude desktop app integrates directly with PowerPoint on Mac and Windows.

Narrative intelligence, not template filling. Claude understands that a CDR deck tells a different story than an executive briefing. Given the same technical content, it rewrites the narrative, selects the appropriate level of detail, and reframes risks for each audience automatically. This is the capability that separates it from simple slide-generation tools.

Capabilities unlocked
Audience
Calibration from technical depth to executive summary. Automatic jargon replacement per audience.
Template
Corporate template application. Brand compliance. Master slide mapping. Logo and colour preservation.
Narrative
Logical story from loose notes. Problem → evidence → risks → next actions. Coherence checking.
Speaker notes
Context-aware notes tailored to the specific presenter's knowledge level and background.
Step-by-step guide
01
Setup · Choose your entry point
Desktop App or Claude Code — both act inside the file directly
Claude Desktop App: integrates with your open PowerPoint file — describe the deck, ask it to revise a slide, or apply your template. Claude Code (terminal or claude.ai/code): point it at a .pptx file; it reads the template structure, applies new content, reshuffles slides, and saves. The Code path is better for batch operations across multiple presentation files.
02
Input · Dump raw material — Claude builds the narrative
Paste notes, emails, or bullets — specify audience and purpose
Provide the raw material and the goal: "These are my integration test results for the thermal subsystem. I need a 10-slide CDR pack for programme managers who are not thermal engineers. Highlight the two anomalies and the mitigations." Claude produces: context → findings → risks → mitigations → schedule impact → next actions. Even badly formatted notes work — Claude reorganises and tightens language automatically.
03
Template · Apply corporate branding without manual formatting
Point Claude Code at your .pptx template
With Claude Code: "Use the branding from this template file. Apply the correct master slide, replace all placeholder text with the new content, add the project logo to the title slide." Claude reads the template structure and populates it correctly — no manual text-box dragging, no accidental font changes from pasting between files. One command reformats the entire deck.
04
Adapt · Audience calibration — two versions, one source
Rewrite specific slides for a different audience without touching the others
"Rewrite slide 3 for the executive steering committee. Remove all TRL references, replace 'delta-V budget' with 'propellant margin', and lead with the cost implication rather than the technical detail." Claude rewrites that slide only. One deck, two audiences, no duplication of effort. The same principle applies to any slide where the audience differs from the primary technical readership.
05
Finish · Speaker notes tailored to the specific presenter
Notes that give the presenter what they actually need
"Write speaker notes for each slide. The presenter is the systems engineering lead — technically strong but new to this programme. Include background context for slides 4 and 7 where the history matters." Claude writes notes that prepare the presenter for likely questions, not just summaries of what is already on the slide. The notes have different value than the deck — they are for the presenter, not the audience.
Track 1 · Augment · Experiment 03
Cowork & Reusable Skills
Building a shared AI workspace that retains your team's standards, templates, and institutional knowledge across every session — automatically.

Without skills, every session starts from zero. Every engineer re-explains company standards, document formats, risk scales, and naming conventions. Skills encode that knowledge once — in a file Claude reads automatically at the start of every session — so the AI behaves like a trained team member from the first message, for everyone, every time.

Two mechanisms
CLAUDE.md — Always-on project memory

The instruction file Claude reads automatically

A plain-text file in your project folder. Contains: company terminology, document standards, risk scoring scales, naming conventions, output format rules. Shared via Git so the entire team uses the same knowledge base with no separate configuration.

Slash commands — One-keystroke workflow triggers

Repeatable tasks without rewriting prompts

Files stored in .claude/commands/. Each contains a prompt template for a recurring task — weekly status report, risk register update, meeting summary. Any team member types /weekly-report to trigger the full workflow immediately.

Step-by-step guide
01
Identify · Find the recurring task
Any task done repeatedly with consistent rules is a skill candidate
Weekly status reports, risk register updates, defect categorisation, meeting minutes formatting, requirement review checklists. The test: "If a new team member needed to produce this output correctly on their first day, what rules would they need to know?" Every answer is a candidate entry for CLAUDE.md.
02
Write · Create the CLAUDE.md file
Encode your team's standards in plain English
In your project root, create a file called CLAUDE.md. Write the rules in plain text: "When producing a risk register always use columns: ID, Description, Likelihood (1–5), Impact (1–5), Mitigation Owner. Calculate Risk Score as Likelihood × Impact. Flag any score above 12 in red." Treat it as an onboarding document — if a new hire needs to know it, the AI needs to know it too.
03
Share · Commit to Git
Every team member instantly has the same skills
Commit CLAUDE.md to the project's Git repository. Every team member who opens the project with Claude Code automatically has access to the same skills — no separate configuration step, no re-explanation of standards. The skill file is version-controlled like any other project document. Changes to standards propagate to the whole team on the next pull.
04
Automate · Add slash commands
One keystroke triggers a complete recurring workflow
Create .claude/commands/ in your project. Add a file named weekly-report.md containing the full prompt template. Any team member types /weekly-report to trigger the complete workflow — project data gathered, report formatted to standard, ready for review. Commands are committed to Git and distributed automatically alongside CLAUDE.md.
05
Evolve · Treat skills as a living document
Skills compound — a well-maintained CLAUDE.md is institutional IP
Each time a team member re-explains a standard to the AI, that explanation belongs in CLAUDE.md. Each time a recurring task is identified, a slash command should be created. After six months, a well-maintained CLAUDE.md represents the accumulated knowledge of how this team produces good output on this specific project. It has value independent of the AI — as a reference, an onboarding resource, and a quality standard.

Skills are institutional IP. A well-maintained CLAUDE.md is not just AI configuration — it is a structured record of how the team works, what standards it applies, and what good output looks like. Maintain it with the same rigour as any other controlled project document.

Track 2 · Automate · Experiment 04
Agents & LinkedIn
An AI that reads the internet and prepares professional content and outreach on your behalf — with human review at every action point before anything is published or sent.

Human-in-loop is a hard design constraint, not a recommendation. An agent that prepares LinkedIn content does so at speed and volume. A single unreviewed post with an inaccurate claim or wrong tone can cause professional damage that far outweighs the time saved. Configure the workflow so the agent prepares and a separate intentional human action publishes. This boundary must not be automated away.

Three agent functions
Research

Industry monitoring

Searches the web for relevant news, papers, announcements, and competitor activity. Returns a structured briefing with sources, summaries, and relevance flags — without opening a browser.

Content

LinkedIn post drafting

Takes research findings and drafts a ready-to-review post: correct tone, call to action, appropriate length. You edit the final 10% — voice and personal judgement — and publish from your account.

Outreach

Connection message drafts

Writes personalised connection requests and follow-up messages based on target profile context and stated purpose. You personalise the details and send from your own LinkedIn account.

Step-by-step guide
01
Setup · Connect a web-search MCP server
MCP gives Claude a new capability — like a plugin
MCP (Model Context Protocol) is a standard connector. In Claude Code settings, add a web-search MCP server. This gives Claude the ability to read live internet data — news, LinkedIn profiles, company pages, arXiv papers — on demand. No coding required; it is a one-time configuration in the settings file. The same MCP pattern is used to connect Claude to other tools: GitHub, Google Drive, Notion.
02
Research · Brief the agent like a research analyst
Structured scope produces a structured briefing
"Search for the top 5 news items this week about model-based systems engineering. Summarise each in two sentences, note the source, and flag any items relevant to space programmes." The agent browses, reads, and returns a structured briefing. This replaces 30–60 minutes of manual scanning per week. The agent maps directly to the Domain 4 (Agent Architecture) research agenda — a concrete experiment in applied orchestration.
03
Draft · LinkedIn post from research findings
The agent handles volume; you handle identity
"Now write a LinkedIn post sharing the most interesting finding. Tone: professional but accessible. Include a question to encourage comments. Keep it under 200 words." The agent produces a ready-to-review piece. You edit the voice, add personal observations, and decide whether to publish. What you bring is judgment and authenticity — which cannot be delegated.
04
Outreach · Prepare personalised connection drafts
The blank-page problem, solved at scale
"Draft a connection request for a systems engineering director at an aerospace firm I want to meet at the conference. Reference our shared interest in MBSE." The agent writes; you personalise the specific details that only you would know — a shared colleague, a talk you both attended — and send from your LinkedIn account. The personal touch remains human; the drafting does not.
05
Gate · Human review before any action
Preparation is automated; publication is not
No content produced by the agent reaches a public platform without human review. Configure the workflow so the agent produces a draft for review, and a separate intentional human action — clicking publish, pressing send — is required for anything to go live. This is not caution — it is correct system design. The agent's contribution is preparation speed, not publication autonomy.

Development process — step by step
01
Setup · Open Claude Code
No installation required for the web version
Go to claude.ai/code in any browser — no installation needed. Or install the CLI: npm install -g @anthropic-ai/claude-code, then type claude. Claude connects to your local files immediately. This is the entry point to the Write phase of the development cycle.
02
Think · Describe the application
Specification in plain English — precision determines efficiency
"Build a web app where my team can submit a document and get an AI summary. It should log every submission with a timestamp, show the result on screen, and let users rate the quality." The precision of this description determines how closely the first implementation matches what is needed. A well-specified requirement from a domain expert produces a near-complete first pass. Vague requirements produce expensive iteration.
03
Write · Review and approve before Claude acts
Claude shows its plan — you confirm before any file is changed
Claude lists every file it will create or modify before acting. You read the plan and confirm. No hidden changes, no surprises. This is the safety mechanism that makes agentic coding trustworthy in practice. The Write phase is not a single pass — it is a tight loop of implement → test locally → refine until the product is ready to deploy.
04
Run · Claude starts the app, checks it, and fixes errors
No need to read error logs or understand stack traces
Claude runs the application, checks it works, and resolves any errors that surface — without requiring the engineer to understand the technical failure. If something is wrong visually or functionally, describe it in plain English. Claude reads the error, diagnoses the cause, and applies the fix. The Run phase ends when the application is stable and behaving as specified.
05
Evaluate · Commit, deploy, and test against criteria
One command from working code to live application
Claude writes the Git commit message, stages files, and pushes to the repository. Deployment services (Streamlit Cloud, Railway, AWS) pick up the code automatically. The Evaluate phase follows: test the deployed application against the criteria defined in Think. If it passes, the cycle is complete. Both applications were built this way — one conversation, one commit, one deployed product.
Track 3 · Build · Experiment 06
On-premises Document Chatbot
An AI that answers questions about your internal documents — running entirely on your own network, with zero data egress. Built and deployed as a production application.

What was shipped. A fully deployed document chatbot: a production web application that indexes internal documents and answers engineering questions with source citations. Stack: Claude Code (build) · Ollama (local inference) · ChromaDB (vector retrieval) · Streamlit (interface). Runs on local hardware. No data leaves the machine. Directly maps to Domain 1 (Dataset Engineering) and Domain 5 (Memory Architecture) in the research agenda.

Technical stack — four components
Build
Claude Code
Wrote the indexing pipeline, retrieval logic, and Streamlit interface. No manual coding.
Inference
Ollama
Local LLM inference. Llama 3 / Mistral. Zero data egress — all inference on local hardware.
Retrieval
ChromaDB
Local vector database. Stores document chunks by meaning. Enables semantic search across the corpus.
Interface
Streamlit
Web interface accessible from any browser on the local network. No installation for end users.
Step-by-step guide
01
Corpus · Gather source documents
The document set is the capability ceiling
Collect the documents you want the chatbot to know: engineering standards, process procedures, lessons-learned logs, ICD documents, SOPs. Answer quality is bounded by source document quality. Well-written, clearly structured documents produce precise, reliable answers. Ambiguous or contradictory source material produces ambiguous answers — this is a data problem, not a model problem. Improving the AI will not fix poor documentation.
02
Inference · Install Ollama
The local AI engine — free, private, runs on your hardware
Install Ollama from ollama.com — free, available for Mac, Linux, and Windows. Pull a model: ollama pull llama3 or ollama pull mistral. Claude Code handles all installation and configuration commands. Once installed, all AI inference runs locally — no API key required, no internet dependency, no data leaving the machine. Also the platform for fine-tuning experiments (Pillar 2 in the AI System Design playbook).
03
Index · Build the vector database
Storing meaning, not keywords — semantic retrieval
Claude Code generates a Python indexing script: reads documents, splits them into chunks, converts each chunk into a vector (a mathematical representation of meaning), and stores them in ChromaDB. This enables semantic search: "how do I handle a thermal anomaly?" finds the right procedure even if the document uses "thermal exceedance" — meaning matches, not just words. Rebuild the index whenever source documents are updated.
04
Interface · Build the chat UI
Browser-based — no installation for end users
Claude Code builds a Streamlit interface: a chat window where engineers type questions in plain English. The pipeline: question → vector search (retrieve relevant chunks) → prompt construction (question + passages) → Ollama inference → answer with source citation. Users see the answer and exactly which document and section it came from. Accessible from any machine on the local network via browser.
05
Evaluate · Test with real questions
Build the eval set before testing — use actual team questions
Test with questions your team actually asks: "What is the approved torque value for M6 fasteners in the structural assembly?" or "What does procedure SE-0042 say about anomaly reporting timelines?" Build an eval set of 15–20 representative questions before the first test run. This is the Evaluate phase from the development cycle. If answers are incomplete, improve source document quality or chunking strategy — not the model.
06
Deploy · Run on the internal network
Accessible to the team as a standard internal web tool
Deploy the Streamlit app on an internal server — a spare workstation or a cloud VM in your private network. Team members access it from any browser. No AI expertise required to use it: type a question, read the answer, check the source. The entire pipeline — documents, index, model, interface — stays inside the network. This is data sovereignty by design.

Data sovereignty by design. This architecture was chosen because sensitive engineering data — specifications, procedures, anomaly reports — must not leave the organisation's network. Ollama (local inference) and ChromaDB (local index) together provide full AI capability with zero data egress. This maps to the Local LLMs row in the AI System Design playbook's capabilities table, status updated from Research to Deployed.
