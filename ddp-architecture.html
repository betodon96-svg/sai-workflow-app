Architecture Reference

Donoso Deep Research

A three-phase deep research workflow engineered for Claude Code environments with restricted HTTPS egress. Abbreviated DDP.

Version 1.0 Repo betodon96-svg/sai-workflow-app Command /ddp UI Claude Code
Core innovation. Claude Code's built-in WebFetch routes through an HTTPS proxy that blocks all outbound CONNECT tunnels (403). DDP replaces that fetch step with a GitHub Actions runner — which has unrestricted internet access — extracting HTML and PDF content and committing the plain text back to the branch. Claude then reads local .txt files, bypassing the proxy entirely. Search and synthesis remain Claude-native.

System Architecture

Phase 1 Search Claude Native

Web search discovers and verifies sources. 6–10 targeted queries yield 12–20 real, deduplicated URLs. URLs from AI memory are excluded — the only cause of 404s in testing.

Claude web search tool URL deduplication Source quality filter
verified URL list (JSON array)
Phase 2 Fetch DDP Custom

GitHub Actions Ubuntu runner fetches each URL. Handles HTML and PDF with three-signal content detection (magic bytes → final URL pattern → Content-Type). Extracts plain text, appends to the cumulative Excel log, and commits .txt files back to the branch.

scripts/fetch_urls.py .github/workflows/fetch-research-urls.yml scripts/requirements-fetch.txt research-logs/fetch-log.xlsx fetched-content/{session}/
.txt files committed to branch → git pull
Phase 3 Synthesize Claude Native

Claude reads local .txt files — no network calls needed. Synthesizes a cited report: executive summary, thematic findings, source quality table, and explicit gaps for any failed sources. Only successfully fetched sources are cited.

Product Completeness

CompleteSearch — Claude's native web search. Real URLs from search results, not AI memory.
CompleteFetch — HTML — httpx with redirect following, lxml/BeautifulSoup text extraction.
CompleteFetch — PDF — Three-signal detection, pdfplumber extraction, size-aware page limits (15–60 pages).
CompleteURL rewriting — arXiv abs→pdf rewrite + general HTML PDF-link follower for other sites.
CompleteLogging — Cumulative Excel log, color-coded by status, hyperlinked URLs, one row per attempt.
CompleteOrchestration — /ddp slash command wires all three phases. Available at user level (~/.claude/commands/) for cross-repo reuse.
CompleteSynthesis — Claude native deep-research synthesis from local text files.
CompleteUI — Claude Code itself. No additional interface layer needed.
PartialJS-rendered pages — httpx fetches static HTML only. Pages requiring JavaScript execution return <100 words. Workaround: Playwright extension (not yet implemented).
ExcludedPaywalled content — McKinsey, Gartner, and similar require authentication. Accepted constraint: use open alternatives in source selection.

Fetch Engine — PDF Detection Logic

Three-signal cascade, evaluated in priority order. Any single signal is sufficient to classify a response as PDF.

SignalCheckReliability
1. Magic bytes First 4 bytes of response body = %PDF Ground truth — server cannot lie
2. Final URL URL after redirects ends in .pdf or contains /pdf/ High — catches CDN-hosted PDFs
3. Content-Type Response header contains pdf Low — last resort, often wrong

Known Constraints

JS-rendered pages
httpx fetches static HTML only. Pages requiring JavaScript return <100 words.
Partial — Playwright extension planned
Paywalled sites
McKinsey, Gartner, and similar require authentication. Always return 403 or redirect to login.
Excluded — accepted limitation
GitHub Actions cold start
Runner provisioning adds ~45s overhead before fetching begins.
Accepted — expected, not an error
Large PDF page cap
pdfplumber extraction capped at 15–60 pages based on file size to prevent multi-minute stalls.
Configurable — adjust in fetch_urls.py
URL hallucination
AI-generated URLs from memory produce 404s. Only search-discovered URLs are reliable.
Solved — Phase 1 enforces search-first
Sequential fetch
URLs fetched one at a time. 24 URLs with large PDFs takes 2–5 minutes.
Accepted — parallel fetch possible future improvement
