Understanding Your AI Toolkit: Three Ways to Work with Claude

Before diving into specific use cases, it helps to understand the three levels at which Claude can work with you — each one more integrated than the last

Level 1 — Conversation

Claude Chat

claude.ai

The simplest entry point. A chat window in any browser: you type, Claude responds. You can attach files, images, or documents for Claude to read and analyse. The output is text, tables, or formatted content that you then use manually.

Key characteristic: Output only. Claude produces; you copy and apply. No direct connection to your files or applications.

Best for: one-off tasks, drafting documents, getting explanations, analysing a document you upload, brainstorming.

Level 2 — Shared Workspace

Claude Cowork (Projects)

claude.ai → Projects

Chat with persistent memory. You define your team's standards, templates, and preferences once — Claude applies them automatically in every future session. Some live integrations are available (Google Drive, GitHub). The AI works like a trained team member who never forgets the house rules.

Key characteristic: Shared context. Your rules, terminology, and workflow knowledge persist across sessions and are available to the whole team.

Best for: recurring team workflows, maintaining standards across projects, building institutional AI knowledge.

Level 3 — Live Interface

Claude Code

claude.ai/code  ·  or terminal CLI

Claude connects directly to your computer, files, and applications. It reads and writes spreadsheets, manipulates PowerPoint files, builds and runs software, deploys applications — all without you copying anything. You give a high-level instruction; Claude acts on your systems directly, shows you what it plans to do, and waits for your approval before making changes.

Key characteristic: Live interface. Claude acts directly in your tools. It is not an advisor — it is an active collaborator with hands on the keyboard.

Best for: building applications, automating workflows, live document manipulation, deploying software.

Why three levels?

The right level depends on your task. Use Chat for exploration and one-offs. Use Cowork when a workflow is established and you want it standardised. Use Code when you want automation — the AI doing the work, not just advising on it.

Do I need technical skills?

No. All three levels work through plain English. Claude handles the technical complexity. You focus on describing what you want. The use cases below show how each level applies to real engineering tasks.

Is my data safe?

Claude Chat and Cowork use Anthropic's cloud. Claude Code can run entirely on your own machine — especially when paired with a local AI model (covered in Use Case 6). Sensitive data stays on your network.

Claude in Excel: Intelligent Data Work

From standardised model generation to live quality assurance — directly inside your spreadsheets

What it is

Claude installs as a native application on Mac (and Windows) and integrates directly with Excel. Once set up, it operates alongside your open spreadsheet — reading data, writing formulas, making changes — without requiring a separate browser window or any copy-paste. Claude Code provides the same live connection from the terminal or web.

Beyond generation

This is not just about creating spreadsheets faster. Claude can apply engineering intelligence to existing data: checking logical consistency, assessing data quality, enforcing standards, and flagging problems before they reach a review.

Standardised engineering models

Requirements traceability matrices, risk registers, WBS structures, ICDs, budget trackers, anomaly logs — Claude knows these formats and can generate, populate, and validate them to your company's specific standards.

Requirements Traceability Matrix Risk Register Work Breakdown Structure ICD Tracker Budget & Cost Tracking Anomaly Log Logical Consistency Checks Data Quality Assessment Cross-sheet Validation Standards Compliance Review Automated Summaries

Step-by-Step Guide

1

Choose your entry point: desktop app or Claude Code

Two paths are available — both provide a live, direct connection to your spreadsheet with no copy-paste:

Claude Desktop App (Mac / Windows) Install the Claude desktop application from claude.ai/download. Once running, Claude integrates with Excel on your machine — it can read your open workbook, respond to questions about it, write formulas, and make edits directly inside the file.
Claude Code (terminal or web) Open Claude Code and point it at any Excel file on your machine. It reads the workbook structure, understands the data, and makes changes directly — useful for batch operations, automation scripts, or working across multiple files.
2

Generate a standardised model from scratch

Describe the model you need: "Create a Requirements Traceability Matrix for a power subsystem. Columns: Requirement ID, Description, Source, Verification Method, Responsible Engineer, Status. Apply our standard colour coding: green = verified, amber = in progress, red = not started."

Claude generates the structure, applies the formatting, and pre-fills example rows. A job that previously took half a day takes five minutes.

3

Run a logical consistency check on existing data

Point Claude at an existing spreadsheet and ask: "Check this risk register for logical errors. Flag any row where the risk score doesn't match the Likelihood × Impact product. Also flag any mitigation marked 'complete' where the residual risk is still rated High."

Claude reads every row, applies the logic, and returns a list of inconsistencies with row references — exactly what a quality reviewer would check, done in seconds.

This type of check is extremely valuable before a formal review: it catches the kind of errors that are embarrassing to have pointed out by a customer.
4

Perform a data quality assessment

Ask: "Assess the data quality of this budget tracker. Flag: missing values, duplicate cost IDs, any line item where the sum of sub-items doesn't match the parent total, and any dates in the past that are still marked as 'forecast'."

Claude produces a structured quality report listing every issue, its location, and a suggested correction. You review and accept the fixes.

5

Revise and reformat to a new standard

When a standard changes or a customer requires a different format: "Reformat this requirements matrix to match the AS9100 template. Add the missing columns, rename the existing ones to match, and preserve all existing data."

Claude restructures the entire workbook. No manual reformatting, no risk of data loss in cut-and-paste operations.

Tip: Ask Claude to "create a backup tab with the original data before making changes" if you want a safety net — it will do exactly that.

Claude in PowerPoint: From Information to Polished Slides

Engineering presentations built from your actual content — not generic templates

What it is

The Claude desktop app integrates with PowerPoint on Mac and Windows — the same installation that connects to Excel. Claude Code can also manipulate .pptx files directly from the terminal. In both cases: the AI works inside the presentation file. No copy-paste, no switching windows.

Beyond slide generation

Claude's value in presentations is narrative intelligence: it understands that a CDR deck tells a different story than an executive briefing, and rewrites the same technical content appropriately for each audience — automatically.

What was done

Generated engineering review decks from raw status notes, applied corporate templates to new project data, produced audience-specific speaker notes, and reformatted existing presentations to new stakeholder requirements.

Step-by-Step Guide

1

Choose your entry point

Claude Desktop App (Mac / Windows) With the Claude desktop app installed, Claude integrates with your open PowerPoint file. Describe the deck you need, ask it to revise a slide, or have it apply your template — Claude acts directly inside the presentation.
Claude Code (terminal or web) Tell Claude Code which .pptx file to work on. It reads the template structure, applies new content, reshuffles slides, and saves — useful for generating multiple decks or applying a template across many files at once.
2

Dump your raw material — Claude builds the narrative

Paste in meeting notes, a status update email, or a list of bullet points. Tell Claude the audience and purpose: "These are my integration test results for the thermal subsystem. I need a 10-slide CDR pack for programme managers who are not thermal engineers. Highlight the two anomalies and what we are doing about them."

Claude transforms scattered information into a logical story: context → findings → risks → mitigations → schedule impact → next actions. The narrative structure is already correct before you see the first slide.

Even poorly formatted notes work. Claude reorganises and tightens language automatically — you do not need to pre-process your raw material.
3

Apply your company template automatically

If using Claude Code: point it at your corporate .pptx template and say "Use the branding from this file. Apply the correct master slide, replace all placeholder text with the content from our status update, and add the project logo to the title slide."

Claude reads the template structure and populates it correctly. No manual dragging of text boxes, no accidental font changes.

4

Calibrate for your audience

The same technical content often needs two versions. Say: "Now create a second version of slide 3 for the executive steering committee. Remove all TRL references, replace 'delta-V budget' with 'propellant margin', and lead with the cost implication rather than the technical detail."

Claude rewrites that slide without touching the others. One deck, two audiences, no duplication of effort.

5

Generate speaker notes tailored to the presenter

Ask: "Write speaker notes for each slide. The presenter is the systems engineering lead — technically strong but new to this programme. Notes should include background context for slides 4 and 7 where the history matters."

Claude writes notes that give the presenter everything they need to deliver confidently, including flagging which slides are likely to draw questions.

Cowork Space with Reusable Skills

Building a shared AI workspace your whole team can plug into

What it is

A "skill" is a saved, reusable instruction set — like a macro but for AI. You write the skill once ("always use our risk scoring scale", "always follow our document naming convention") and every future session applies it automatically.

Why it matters

Without reusable skills, every engineer has to re-explain company standards to the AI each time. Skills encode your team's knowledge once, so the AI always behaves like a trained team member from the first message.

What was done

Defined custom skills inside Claude Code for document formatting, risk categorisation, and status-report generation. These are now available to every team session automatically — shared via the project repository.

Step-by-Step Guide

1

Identify a recurring task

Think about something your team does repeatedly: writing a weekly status report, categorising defects, formatting meeting minutes, scoring risks. Any task where the format and rules are consistent is a candidate skill.

2

Write the skill as a CLAUDE.md file

In your project folder, create a file called CLAUDE.md. Inside, describe the rules Claude should always follow: tone, format, company terminology, and any standard templates to use.

Example entry: "When producing a risk register always use columns: ID, Description, Likelihood (1–5), Impact (1–5), Mitigation Owner. Always calculate the Risk Score as Likelihood × Impact. Flag any score above 12 in red."
3

Share the project with your team

Commit the CLAUDE.md to a shared Git repository (e.g. GitHub). Every team member who opens the project with Claude Code instantly has access to the same skills — no extra configuration, no re-explaining the rules.

4

Add custom slash commands

In .claude/commands/, add a file like weekly-report.md with a template prompt. Any team member can then type /weekly-report in the AI chat to generate a formatted report instantly, using the current project data.

5

Iterate and expand

As the team uses the skills, add new ones based on feedback. Skills evolve with your processes — they are living documents, not one-time setups.

Treat CLAUDE.md like an onboarding document. If a new hire needs to know it to work correctly on this project, the AI needs to know it too.

Agents Acting on Your Behalf: Web Research & LinkedIn

An AI that reads the internet and acts on professional platforms for you

What it is

An AI "agent" is Claude running a series of tasks autonomously: it can search the web for relevant news, summarise competitor activity, draft LinkedIn posts, and prepare outreach messages — all from a single high-level instruction.

Why it matters

Monitoring industry developments, preparing thought-leadership content, and maintaining a professional LinkedIn presence are high-value but time-consuming. An agent does the grunt work; you approve and publish.

What was done

Configured Claude Code with web-search capabilities to research industry topics, draft LinkedIn posts based on findings, and prepare personalised connection messages — all ready for human review before any action is taken.

Step-by-Step Guide

1

Enable web search in Claude Code

In the Claude Code settings, connect a web-search MCP (Model Context Protocol) server. This gives the agent the ability to read live internet data — news, job postings, company pages — on demand.

MCP is a standard connector: think of it like a plugin that gives the AI a new superpower. No coding required to enable it — it is a one-time configuration in the settings file.
2

Define a research task

Tell the agent: "Search for the top 5 news items this week about model-based systems engineering. Summarise each in two sentences, note the source, and flag any items relevant to space programmes."

The agent browses the web, reads articles, and returns a structured briefing — in the time it takes to pour a coffee.

3

Ask it to draft LinkedIn content

Continue: "Now write a LinkedIn post sharing the most interesting finding. Tone: professional but accessible. Include a question to encourage comments. Keep it under 200 words."

The agent produces a ready-to-post piece of content — no blank page, no guessing at the right tone. You edit the last 10% and publish.

4

Prepare outreach drafts

Ask: "Draft a connection request message for a systems engineering director at an aerospace firm I want to meet at a conference. Reference our shared interest in MBSE."

The agent writes a personalised, professional message. You adjust the personal details and send from your own LinkedIn account.

5

Always review before publishing

The agent prepares; a human approves. This "human-in-the-loop" step ensures accuracy, tone, and compliance. The AI handles volume and research; you handle judgement and identity.

Important: Never configure an agent to post or send without a human review step. Speed is not worth the risk of an unintended public message or an inaccurate claim.

Step-by-Step Guide: Build Your Own App with Claude Code

1

Open Claude Code

Go to claude.ai/code in any browser — no installation needed. Or install the CLI in a terminal with npm install -g @anthropic-ai/claude-code and type claude to start.

2

Describe your application in plain English

Tell Claude what you need: "Build a web app where my team can submit a document and get an AI summary. It should log every submission with a timestamp, show the result on screen, and let users rate the quality."

The more specific you are about who will use it and what they need to do, the better the first version. You can always iterate — but a clear brief saves iterations.
3

Review and approve changes

Claude lists every file it will create or modify before acting. You read through the plan and confirm. This gives you full visibility — no surprises, no hidden changes, no code running without your knowledge.

4

Run the app and test it

Claude runs the application, checks it works, and fixes any errors — often without you needing to do anything. If something looks wrong, describe it in plain English: "The button is too small on mobile" or "The summary is being cut off."

5

Commit and deploy

Claude writes the Git commit message and pushes the code to your repository. From there, services like Streamlit Cloud, Railway, or AWS deploy it automatically. Your application is live for the team.

Both applications above were built this way: one conversation, one commit, one deployed product.

Chatbot Building with RAG and Local LLMs

An AI that knows your documents — and runs entirely on your own network

What is RAG?

RAG (Retrieval-Augmented Generation) means the AI searches your documents before answering. Instead of guessing or hallucinating, it finds the relevant passage in your actual procedures and quotes from it. Answers are traceable to a source.

What is a local LLM?

A local LLM is an AI model that runs on your own machine or server — not in any cloud. Your documents and queries never leave your network. This is critical for confidential engineering data, sensitive programmes, or air-gapped environments.

What was shipped

A fully deployed Ollama-powered document chatbot: a production web application that indexes internal documents and answers team questions in plain English, with source references, running entirely on-premises.

Step-by-Step Guide: Build a Chatbot That Knows Your Documents

1

Gather your source documents

Collect the PDFs, Word files, or web pages you want the chatbot to know: engineering standards, process guides, lessons-learned logs, ICD documents, SOPs. The chatbot is only as good as the documents you give it — quality in, quality out.

2

Install Ollama and choose your model

Install Ollama on your machine or server — it is free and runs locally. Choose a model: Llama 3 or Mistral work well for engineering documents. Claude Code handles the installation commands and configuration.

Ollama is the local equivalent of the Claude cloud API. Once installed, the AI runs on your hardware with zero internet dependency.
3

Build the document index

Claude Code generates a Python script that reads your documents, breaks them into searchable chunks, and stores them in a local vector database (ChromaDB or Qdrant). This index is what the chatbot searches when a user asks a question.

A vector database stores meaning, not just keywords. Asking "how do I handle a thermal anomaly?" finds the right procedure even if it uses the term "thermal exceedance" — because the meaning matches, not just the words.
4

Build the chat interface

Claude Code creates a Streamlit web interface. Engineers type questions in plain English; the app searches the document index, retrieves the relevant passages, feeds them to Ollama, and displays a precise answer — with the source document and page number cited.

5

Test with real team questions

Ask the chatbot what your team actually asks: "What is the approved torque value for M6 fasteners in the structural assembly?" or "What does procedure SE-0042 say about anomaly reporting timelines?"

If answers are incomplete, the fix is almost always improving the source documents — not the AI model. Well-written procedures produce well-grounded answers.

6

Deploy to the team

The chatbot runs as a web application on your internal server. Team members access it from a browser — it looks and works like any internal tool. No AI expertise needed to use it. The whole pipeline — documents, index, model, interface — stays inside your network.
